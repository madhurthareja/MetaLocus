## Context

`docs/brainstorm-2026-11-03.md` measured two existing bugs that matter more than any of the five proposed features:

- **A: left/right is a coin flip on SANPO.** Image-side agreement is 55% shipped vs 99% corrected. Causes:
  - SANPO raw poses are already OpenCV-camera / Z-up world, so `_R_SANPO_LOCAL_FROM_OPENCV` is wrong (a det −1 reflection).
  - `frames.py` treats world Y as vertical.
  - 271/539 frames have zero wearer velocity, so the heading falls back to straight up.
- **B: ~94% of critical alerts are velocity noise.** 342/539 frames are critical shipped vs 18 under a static world. Causes:
  - per-frame position noise (median 0.14 m, p90 0.70 m)
  - velocity left frozen on unobserved nodes (e.g. 112 m/s "trucks")

The follow-up advice adds class-dependent memory. Static things persist; movable things go stale fast. I agree with it, with one correction: `compute_edges()` (`src/locus/memory/edges.py`) ignores `confidence`. Faster decay alone changes no alert. Stale movers must be excluded from alerting explicitly, and implausible velocity samples rejected. It also suggests a head-turn demo, which no cached SANPO session contains (measured: 0 head-off-heading >35° episodes while walking in sessions 1–2; session 3's only spike is a velocity glitch).

Outcome: a regenerated demo that says the correct side, alerts only on real geometry, and speaks less. Docs and writeup claims get corrected to match. Features #1, #4, #5 and green-path are dropped as builds and moved into the writeup.

## Phase 1: Fix A, geometry (≈3.5 h)

1. **Loader:** in `src/locus/data/sanpo_loader.py`, set `_R_SANPO_LOCAL_FROM_OPENCV` to identity. Rewrite the rotation-convention docstring and comment: the reprojection result, the identity convention, Z-up, and why the earlier −X/22° result was an artifact.
2. **World-down parameter.** Thread one parameter through the frame code:
   - `frames.py`: rename `_WORLD_UP` → `_WORLD_DOWN_DEFAULT = [0,1,0]`, with a comment that the synthetic world is OpenCV-axis, so +Y is down. `world_to_body(..., world_down=...)` passes it to the existing `body_rotation_from_velocity(..., up_world=)` (its math is already correct when given gravity-down).
   - `edges.py` `compute_edges(..., world_down=)`: use it for `world_to_body`, and set `elevation_delta_m = -dot(relative, world_down)` (replacing `relative[1]`).
   - `graph.py` `SpatialMemoryGraph(world_down=...)` stores it and passes it in `edges()`.
   - Defaults keep synthetic and every existing test unchanged.
   - Add `world_down` to the dataset objects: a `SanpoSequence.world_down = (0,0,-1)` attribute, and the same in the AEA loader (also measured Z-up). Callers read `getattr(seq, "world_down", default)`.
3. **Wearer heading.** Add `smoothed_heading_velocity(positions, timestamps, window_s=1.0, min_speed=0.3)` to `src/locus/geometry/kinematics.py`, reusing `finite_difference_velocity`. It does a 1 s causal window, horizontal only (projected perpendicular to `world_down`), and holds the last heading when below `min_speed`.
   - It returns `(heading_velocity, speed)`. The body frame uses the held heading, and closing speed uses the real (possibly zero) velocity.
   - Use it in `scripts/generate_dashboard_data.py` (lines ~298–302 and 340) and `scripts/run_real_sequence.py` (~163/205). `eval/conditions.py` stays as-is: synthetic only, constant velocity.
4. **Tests** (`tests/test_sanpo_loader.py`):
   - The heading test computes yaw in the plane perpendicular to `world_down`. Assert median <25° (measured 14.7°).
   - Replace `test_camera_right_maps_to_positive_body_frame_bearing` with an image-side test: a synthetic point at camera-right, on frames where the camera faces within 20° of travel, must have positive bearing on >90% of frames.
   - Add a cheap reprojection test: identity convention beats the old matrix on a few frame pairs, a small port of the scratchpad `convention_search.py` scoring.
   - Add a unit test in `tests/test_geometry.py` that a Z-up world with `world_down=(0,0,-1)` puts world +X on the right when walking +Y.

## Phase 2: Fix B, velocity + class-dependent memory (≈1.5 h)

All changes go in `src/locus/memory/graph.py` / `edges.py`. Unknown concepts keep today's behaviour, so the existing synthetic memory tests stay green.

- **`STATIC_CONCEPTS`** (pole, tree, hydrant, bin/trash can, lamppost/street lamp/light, sign, traffic light, bench, …), with a normalized match on the concept string. These nodes keep velocity at 0 and use the current long half-life and eviction.
- **`MOVABLE_CONCEPTS`** (person, car, truck, van, taxi, bus, bicycle/cyclist, scooter, dog), with `MAX_SPEED_MPS` per class (person 3, bike/scooter 8, vehicles 20):
  - Outlier gate: an instantaneous velocity sample above the class max is treated as an association/lifting jump. Skip the velocity update but still update position.
  - Short persistence: half-life ≈1 s, eviction ≈4 s (class-dependent overrides on `graph.step`).
  - **Stale-mover exclusion:** `compute_edges` skips movable nodes not observed for >`MOVER_STALE_S = 0.75` s. No extrapolation and no frozen velocity reach TTC. The node stays in memory, so the 3D view still shows it fading.
- Tests:
  - a static concept gets zero velocity under jitter
  - a mover with an injected 5 m jump keeps a sane velocity
  - a mover unobserved for 1 s produces no edge
  - an unknown concept behaves as before

## Phase 3: Alert policy, #2 + #3-CPA (≈2–2.5 h)

In `scripts/generate_dashboard_data.py`'s selection block (lines ~342–357):

- **CPA:** add `cpa_m` and `tcpa_s` to `Edge` (`types.py`), computed in `compute_edges` from horizontal relative position and velocity. A static object is speakable as critical/advisory only if `cpa_m < CPA_GATE_M = 1.0`. This removes "pole off to the side" alerts.
- **Novelty as state change:** a per-node `last_announced = (tier, clock_bucket)`. Speak only on a new node, a tier change, or a ≥2-hour clock change.
  - It composes with the existing cooldown: novelty filters candidates, cooldown paces the channel. Critical escalation bypasses both, as today.
- Mirror the same rules in `dashboard/static/js/state.js` (`mostUrgentEdge`/playback) so the UI and pipeline agree. Emit `cpa_m` and `spoken: bool` per edge in `timeline.json`, so the JS reads the decision rather than re-deriving it.
- Unit-test the selection function (extract it as a pure function `select_spoken_edge(edges, nodes, state, t)` so it's testable).
